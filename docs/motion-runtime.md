# Optional universal motion runtime

The existing sprite/WebP path remains the production default:

```text
ClipLibrary -> SpriteAnimator -> ActorPresentation -> PetView
```

This document defines a second, opt-in path that consumes
`mypet-motion-v1` generated by the private asset forge:

```text
H3 accepted animation
        |
        v
mypet-motion-v1
        |
        v
UniversalMotionDocument        (MyPetContent)
        |
        v
SkeletonMotionPlayer
        |
        v
MotionRetargeter + SkeletonRig2D
        |
        v
RetargetedSkeletonPose         (MyPetRender)
```

## Why this path exists

H3/WebP remains better for highly authored or exaggerated animation. Universal
motion targets a different cost problem: one common walk/run/wave motion should
not have to be regenerated for every character.

The motion stores **directions**, while a target rig owns segment lengths.
Therefore one H3-derived clip can drive a short character, a normal character,
and a tall character without inheriting the source actor's limb lengths.

## V1 contract

The public runtime accepts only:

- `format = mypet-motion-v1`
- `skeleton = coco17-v1`
- monotonic, contiguous frames
- normalized hip-centered joints
- length-free bone direction vectors

`root_screen` is decoded and exposed but does not move an AppKit actor in V1.
This prevents an experimental analysis track from changing existing world/body
semantics.

## Deliberate non-goals

This PR does not:

- change `ActorPresentation`
- select skeleton playback for any current pet
- add Metal mesh skinning
- define character mesh/weight files
- package shared motion in `.mypetpack`
- derive hitboxes, contacts or root motion

Those steps can be added independently after the decoder/retarget contract is
validated against real H3 output. Existing sprite tests and behavior remain the
compatibility baseline.
